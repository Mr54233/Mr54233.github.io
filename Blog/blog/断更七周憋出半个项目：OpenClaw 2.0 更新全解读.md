# 断更七周憋出半个项目：OpenClaw 2.0 更新全解读

> 2026 年 8 月 30 日，OpenClaw 发布了官方称之为"史上最大更新"的 2.0 版本（对应正式版本号 v2026.8.1）。官方博客的标题很自嘲——《OpenClaw 2.0, Accidentally》，"一个意外的 2.0"。

## 一、这条"龙虾"经历了什么

OpenClaw 外号"龙虾"，是一个开源 AI 助手框架：跑在你自己的电脑上，通过 WhatsApp、Telegram、iMessage 这些你本来就在用的聊天软件与你协作，帮你收发邮件、整理收件箱、管理任务。今年 2 月，创始人 Peter Steinberger 加入 OpenAI，项目移交给独立的 OpenClaw Foundation 运营。此后它被后起之秀 Hermes Agent 压制，声量日渐走低，甚至从 7 月中旬的 v2026.7.1 之后停更了近 7 周——要知道这个团队此前曾在 230 天里发了 106 个版本，平均一两天一版。社区一度以为龙虾要凉了。

结果是憋了个大招：**933 位贡献者参与（其中 569 位是首次贡献），合入超过 16,000 个 PR——约占 OpenClaw 历史上全部已合并 PR 的一半**。相当于这次更新"吞掉了"半个项目的历史工作量。

为什么叫"意外"？官方博客解释：团队最初只想做两件事——简化安装流程、把浏览器端体验重做。但要把这两件事做对，清理工作就得蔓延到 OpenClaw 的其余部分，改着改着就成了 2.0。

## 二、核心变化一：安装，从"填表"到"复用"

这是 2.0 的第一主题。以前装 OpenClaw，你得手动编辑一堆配置文件，本质上是个开发者工具的入场券。现在首次安装会直接复用你电脑上已有的 AI 资源：

- 已登录的 **ChatGPT / Claude / Codex 订阅凭据**，验证通过才保存；
- 已有的 **API key**；
- 自动发现 **Ollama / LM Studio 本地模型**。

大量配置项被砍掉或移出初始安装流程，剩下的设置在你开始第一次对话之后，再通过和 Claw 聊天逐步完成。模型侧也有动作：OpenAI 新装默认 GPT-5.6，默认上下文升到 64K，新增进程内 GGUF 推理，托管 llama-server 替换了老的 node-llama-cpp。

移动端同样重做了配对：iOS / Android 优先用二维码 / 设置码配对，会明确显示 Full / Limited 访问级别，未加密连接自动降为受限模式。甚至 Claude、Codex、Hermes 的旧数据都可以导入——36 氪实测，配置向导能发现本机已装的 Codex，Hermes 的记忆可一键迁入，摆明了是来抢用户的。

## 三、核心变化二：Web 界面推倒重建

浏览器是多数人接触 OpenClaw 的入口，这次被重建为"一等公民"体验：

- **以聊天为中心**，打开直接进入与 Claw 的对话，Overview 页取消；
- 侧栏可调宽，会话支持分组、分页、固定、批量操作，转写文本可按精确词句搜索，还能从搜索结果直接跳回原上下文；
- **新建会话变成一个完整的设置界面**：可选 agent、模型、推理级别、工作区、运行机器；
- 会话归档成为一等功能（可撤销恢复），还可以在 Gateway 与 runner 之间**把会话搬到云机器上**继续跑。

配套的交互也升级了：结构化提问（卡片/按钮，不再只有聊天气泡）、可钉在会话仪表盘上的 widget 组件、跨重载保留的子任务进度卡片、全链路不丢关联的音视频富媒体（移动端支持原生播放控制和视频上传）。

## 四、核心变化三：从单机助手到多人协作

**共享云端会话**是这次最有想象力的功能。以前的痛点是：一个任务跑到一半，想拉同事进来接手，就会丢失 Claw 已经积累的上下文。现在你可以邀请合适的人加入实时工作，或者把任务完整移交而保留全部上下文。官方说他们自己就用这个功能来开发 OpenClaw 本身。

配套的还有**内置记忆系统**（取代原来的 QMD 插件）：Claw 能回忆其他对话的上下文，用户可以搜索、检查、删除这些记忆。默认行为也变了：会话跨天保留、自动自学习默认开启——不想要的话记得手动关。

## 五、安全：这次是动真格的

安全机制是被各家评测夸得最多的部分：

- **私密凭据掩码输入**：agent 需要密钥时以掩码方式提交，值不进聊天记录、不进模型上下文；
- **自动化一次性授权**：权限精确到单次操作，事后可审查、可撤销，任务内容变了要重新批准；
- 私有凭据不进聊天记录，权限授权仅限单次精确操作。

自动化功能整体翻新：cron 改名 Automations，错过的任务会自动补跑，可查看任务状态。消息可靠性也修了：重启不再丢消息、不再重复发送。

## 六、两个破坏性变更和升级注意事项

**破坏性变更一：OpenProse 插件移除。** 内置插件和 `/prose` 命令被删除，需要运行 `openclaw doctor --fix` 清理残留配置；`.prose` 源文件会保留，按官方迁移指引转用上游 Agent Skill。

**破坏性变更二：OpenAI 路由迁移。** 所有 `codex/*`、`openai-codex/*` 的模型引用、provider 配置、存储会话和自动化路由统一迁移到 `openai/*`。冲突会被标记待人工处理，doctor 可自动完成大部分迁移。

另外几个坑要留意：

1. **版本号乌龙**：发布为 `2026.9.1-beta.1` 的包实际上是 `2026.8.1-beta.4`，官方明确说它不应被视为比稳定版 2026.8.1 更新。稳定用户请直接装 2026.8.1。
2. **存储迁移到 SQLite**：会话与转写记录迁入 SQLite，迁移后创建的会话在旧版本里不可见，想降级得先用当前 CLI 恢复归档的旧转写文件。
3. **插件作者注意**：外部插件需迁移到 `openclaw/plugin-sdk/` 新接口，9 月 1 日起旧子路径导入进入弃用门槛。

官方推荐（顺序不可颠倒）：

```bash
cp -r ~/.openclaw ~/.openclaw.bak-$(date +%F)   # 1. 先备份
openclaw update                                   # 2. 升级
openclaw doctor --fix                             # 3. 迁移清理
openclaw doctor                                   # 4. 验证 Gateway
openclaw update repair                            # 5. 补装缺失 provider 包后重启
```

核心原则就一句：**先备份，再 doctor --fix**，否则配置可能被直接改掉。

## 七、值不值得升：外界怎么说

好评集中在：安装门槛肉眼可见地降低、UI 现代化、安全和记忆机制实用。有评论认为这让开源 Agent 领域"不再只有 Hermes 一种声音"。

批评也没客气：网关、权限、创建 agent（要手输 `/approve` 命令）这些环节仍然是一股开发者工具味；新建会话按钮藏在左上角一个小加号里；非开发者吐槽安装流程依然涉及大量命令行操作，和 Hermes 开箱即用的体验差距明显。

**结论**：断更七周换来的，仍是一个面向开发者的产品，离"大众化"还有距离。但 OpenClaw 以独立基金会的身份重新回到了起跑线上——不绑定单一公司、单一模型或单一 AI 供应商，这本身在当下的 Agent 竞赛里就是个差异化卖点。至于能不能从 Hermes 手里夺回用户心智，就看接下来几个版本的迭代速度了。
